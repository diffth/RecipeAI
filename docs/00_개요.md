# RecipeAI 개요

## 한 줄 소개

요리 사진을 찍으면 무슨 요리인지 알려 주고, 영양을 평가하고, 최종적으로는 레시피까지 알려 주는 서비스.

## 목표

| 단계 | 내용 | 상태 |
| --- | --- | --- |
| 1차 MVP | 사진 → 요리 이름(신뢰도 포함) + 1인분 영양 평가 | 구현 완료, 실제 인식은 API 키 넣고 확인 필요 |
| 2차 | 인식한 요리의 레시피(재료·분량·조리 순서) 제공 | 예정 |
| 이후 | 기록 저장·로그인, 공공 영양 DB 연동, 배포 | 미정 |

## 사용 흐름 (MVP)

1. 사용자가 웹 페이지에서 사진을 찍거나(모바일 카메라) 파일을 고르거나 드래그해서 올린다.
2. "분석하기"를 누르면 서버가 사진을 Gemini에 보낸다.
3. 결과 화면에 다음이 나온다.
   - **요리 이름**: 한국어·영어 이름, 신뢰도(%). 60% 미만이면 "확실하지 않음" 표시, 다른 후보 최대 3개.
   - **영양 평가**: 가정한 1인분 분량, 칼로리(kcal), 탄수화물·단백질·지방(g, 칼로리 비율), 당류·식이섬유(g), 나트륨(mg).
   - **한 줄 평가**: 요약, 장점, 주의점.
4. 음식이 아닌 사진이면 "음식 사진이 아닌 것 같습니다"라고 알린다.

## 구성

| 파일 | 역할 |
| --- | --- |
| `app/page.tsx` | 업로드·미리보기·결과 화면 |
| `app/api/analyze/route.ts` | `POST /api/analyze`, 형식(JPG·PNG·WEBP·HEIC)·크기(8MB) 검증 |
| `lib/analyze.ts` | Gemini 호출(JSON 구조화 출력), zod로 응답 검증 |
| `lib/nutrition.ts` | 탄단지 칼로리 비율 계산 |

실행 방법은 루트의 `README.md`를 참고한다.

## 한계와 주의

- 영양 수치는 사진 속 양을 눈대중한 **추정치**다. 의료·식단 관리 기준으로 쓰면 안 된다.
- 비슷하게 생긴 요리(김치찌개/부대찌개 등)는 헷갈릴 수 있어 신뢰도와 후보를 함께 보여 준다.
- 사진은 저장하지 않고 분석 요청에만 쓴다. 단, Gemini API로 전송된다.
- Gemini 호출마다 API 요금(또는 무료 할당량)이 든다.
